视觉主题 v0.2.0

从浅色卡片风整体换成 深底 + 霓虹 + 点阵字。核心是两套原生点阵字体： ASCII 用 M5GFX 内置的 Font8x8C64（C64 8×8 点阵，行优先，覆盖全 ASCII 含小写）， 中文用 efontCN_16（16×16 点阵）。两者都是位图，放大只会变成更大的方块、不会糊， 这正是像素风想要的。

元素取值说明
屏幕底0x05070A近黑，上面铺 16px 间距的暗网格点（CRT 底纹）
面板底0x0B1017卡片 / 大按钮底
主文字0xB8C7D6冷白，次级用 C_DIM
霓虹六色 青 / 绿 / 琥珀 / 品红 / 紫 / 红 —— 一应用一主色
组件做法
drawFrame()HUD 边框：1px 细框 + 四角 3px 实心角标（不用圆角，圆角不像素）
drawPxIcon()8×8 位图图标（8 字节，每字节一行，bit7=最左），scale=3 画成 24×24
drawProgressBar()分段块进度条，每 6px 一块 + 2px 间隔
drawRow() / drawTitle()终端列表行（暗色标签 + 霓虹 ASCII 值）、> 标题；标签中英文都行，字体会自动选
drawKeyBox()方角按键块；filled=true 时是霓虹底 + 黑字（反白高亮）
clearArea()局部擦除并补回网格点，避免清区域留下底纹缺口
drawCenterText()水平+垂直居中，并按内容自动选中文/ASCII 点阵（双语排版都用它）
setAutoFont() / hasCJK() / textHeight()按「有没有非 ASCII 字节」选字体；字高 16（含中文）或 8（纯 ASCII）

双语（简中 / 英文）v0.3.0

界面文字全部走 S(StrID) 取串，不要写死字符串。切换后写进 NVS，掉电不丢。

怎么切说明
设置 → 语言 行点右侧方块在 简中 / ENGLISH 之间切，立即重绘全界面（含导航条应用名）
串口 lang cn / lang en不带参数直接 lang = 反向切换
英文模式长什么样纯 ASCII + 8×8 点阵，更像真正的终端：日期 2026-09-20、星期 SUN、按钮 REC / SEND / CANCEL
英文串必须纯 ASCII。8×8 点阵里没有汉字，混进 ·、→ 这类非 ASCII 符号（UTF-8 里 >= 0x80） 会被 hasCJK() 判成中文、改用 16×16 点阵，排版行高就变了。所以英文串里统一用 / 代替 ·。
两张表靠 static_assert 对账：数组故意不写长度，跟 StrID 枚举数量不一致时直接编译不过， 不会出现「中文对英文串味」这种难查的 bug。

手势：左缘右滑返回 v0.1.3

CoreS3 是电容触摸屏，M5Unified 的 Touch_Class 底层自带 flick / drag / hold 状态机（判定「手指动了多少」），但没有「这个动作是什么意思」这一层—— 手势语义由外壳自己写。

判定条件（三条同时满足）取值
起手点在屏幕左缘base_x <= GEST_EDGE(40)
向右位移够远distanceX() >= GEST_MIN_DX(44)
上下没跑偏|distanceY()| <= GEST_MAX_DY(44)（避免竖向拖被误判）
移动阈值（交给 M5Unified）setFlickThresh(16)：小于它的抖动仍算点击
点击是「抬手才派发」，不是「按下即派发」。 否则按下那一帧就被应用消费掉了，手势根本没有介入的机会。改成抬手派发后， 按下之后可以靠滑动取消这次点击——和手机上的行为一致。
「返回上一级」统一走 goBack()：先问应用 onBack()， 应用返回 false 或没实现（nullptr）才回桌面。v0.4.0 起控制器只剩一页 （预设二级页已删），onBack() 空着，留给将来带二级页的应用。

★ 最大的坑：del 键发的是 0x7F，不是 0x08。 Keyboard3 上有两颗删除键：标 del 的那颗 = 0x7F，标 ⌫/BS 的那颗 = 0x08 （键码定义在 M5Faces_Keyboard3.hpp 的 keyboard3_key_t 枚举里，旁边还有 FN+方向键=180-193、ALT+字母=144-176 等扩展码）。 v0.4.8 及以前只映射了 0x08，所以按 del 键一点反应都没有 —— v0.4.9 已把两颗都接上取消。
改键前先确认键码：串口发 key <0-255> 会走同一条 onKey 派发路径 （例：key 127 == 按了 del 键），不用真的去按。

串口命令 调试

  • status — 当前应用/蓝牙/键盘/电量/亮度/休眠
  • apps — 列出所有应用编号与名字（跟随当前语言）
  • lang cn / lang en — 切语言，写入 NVS；单输 lang = 反向切
  • launch N — 直接启动第 N 个应用
  • home — 回桌面
  • back — 返回上一级（等价于左滑手势）
  • unpair — 重启蓝牙广播（重新配对用）
  • bright 0-255 — 改亮度
  • sleep 秒 — 改息屏时间，0 = 常亮
  • focus 0-7 — 新建对话后的聚焦方式（0=OFF 默认，1-3=S-TAB1-3，4-6=TAB1-3，7=WAKE 实测会带走焦点，别用）
  • fdelay <ms> — 聚焦前先等多久（200-5000，默认 1800）
  • rec 0|1 — 录音方式（0=WorkBuddy 内置语音 Cmd+D，1=macOS 听写）
  • clear 0|1|2 — 取消键档位（0=ESC，1=WIPE，2=ESC+WIPE 默认）
  • act rec|send|cancel|new|prev|next — 直接跑固件真实按键路径（自测用，别手动拼键）
  • key <0-255> — 模拟 Keyboard3 物理按键，走同一条 onKey 派发路径（key 127 = 按 del，key 32 = 空格，key 13 = 回车）。验键位映射用
  • music — 打印歌曲元数据与封面收发进度（art=已收/总长 (ready)）
  • time [YYYY-MM-DD HH:MM:SS] — RTC 对时（v0.5.1）。不带参数 = 打印当前 RTC；带参数 = 写入，星期自己算
  • note — 打印记事本状态（fs/sub/sending/queued/sent/len/draws）。 draws 是重绘次数：静置时它不该涨，涨了说明又退回按节拍重绘了
  • note push <文本> — 走真实发送路径推一条速记（不碰屏幕就能验链路，v0.6.0）
  • note type <文本> — 逐字符喂给 appNoteKey() 再补 ALT+S，等于「模拟真人在 Keyboard3 上打完这行并按发送」。验按键映射（含 0x08/0x7F 退格、0x0D 换行）用这条
  • fs — flash 文件系统体检：分区信息（label=lfs）/ 挂载 / 写测试 / 列根目录；找不到分区时会把整张 data 分区表打出来（v0.6.0）
  • fs2 — 更底层：裸分区 erase+write+read 读回校验，并对比 open("/x") 与 open("/littlefs/x")
  • reboot — 硬重启（烧录后必发一次，fw.sh 已自动带上）

怎么加一个新应用 扩展

  • 1. 新建 app_xxx.ino，实现 5 个入口函数（onBack 可选）
  • 2. 在 shell.h 里声明这些函数
  • 3. 在 i18n.h 的 StrID 加应用名，并在 i18n.ino 两张表里各补一条
  • 4. 在 cores3_shell.ino 的 g_apps[] 加一行：nameId + 霓虹主色 + 8×8 图标
  • 5. 图标是 8 字节位图，0x80 是最左像素（跟 C64 字体数据同格式）
// app_xxx.ino
#include "shell.h"
static const uint8_t ICON[8] = {0x18,0x3C,0x7E,0x5A,0x5A,0x7E,0x3C,0x18};
void appXxxStart() { clearCanvas(); drawTitle(40, S(S_XXX_TITLE), C_CYAN); }
void appXxxLoop()  {
  static uint32_t last = 0;
  if (!uiTick(last)) return;    // 统一 1Hz 节拍
  // 再做内容脏检查：值没变就直接 return，屏幕不闪
}
void appXxxTouch(int16_t x, int16_t y) { /* y>=CANVAS_Y(36) */ }
void appXxxKey(uint8_t raw) { /* 0x0D 0x1B 0x20 ... */ }
void appXxxStop()  { }
// 可选：返回 true = 左滑/Esc 先在应用内部返回（二级页）
bool appXxxBack()  { return false; }
坑 1：所有 .ino 会被合并成一个编译单元， static const 常量和 static 函数不能跨文件重名。 常量加应用前缀（PMO_X、SEN_X），同名辅助函数改名（infoRow / senLine）。
坑 2：导航条占 y < CANVAS_Y(36)，应用内容从 y >= 40 开始排， 底部别超过 226（240 高屏，中文一行 16）。
坑 3：ASCII 数值区只能放 ASCII——用 8×8 点阵字体画中文会出空白， 中文一律走 setCnFont()（如电量行写 93% BAT 而不是 93% 放电中）。
坑 4（双语）：界面文字一律 S(StrID)，别写死；成组的串（星期、休眠档） 在枚举里必须连续，代码靠「基址 + 下标」取。垂直居中用 textHeight(s) 算， 别写死 16——英文模式下是 8，写死会整体偏上。

已知约束 重要

  • 灯带必须保持关闭（ENABLE_BOTTOM3_LED 0）：Adafruit NeoPixel 在 ESP32-S3 上有已知 bug（官方 issue #429），show() 走 RMT，无线电繁忙时触发断言并无限重启。开 BLE 后必现。
  • 默认分区只有 3MB APP 且无 OTA 槽：现在是「一个固件装所有应用」，加应用要重新编译烧录。想做成运行时安装/卸载，得先写自定义分区表（启动器 1.5MB + 4×2MB 应用槽）。
  • 改代码后必须 compile --clean：arduino-cli 的缓存不会因为 config.h 变化而失效，容易烧进旧固件。
  • 烧录前设备要接 USB 并开机：串口是 /dev/cu.usbmodem*，但编号每次插拔/换 USB 口都会变 （实测见过 101 和 2101）——一律自动探测，别硬编码（fw.sh / ser.py 已这么做）。找不到就单击电源键开机再试。
  • RTC 没有后备电池：掉电或重烧后时间归零，而设备本身没有任何对时来源（没 Wi-Fi、BLE 也不给时间）。 用串口 time YYYY-MM-DD HH:MM:SS 对时，或直接跑 cores3-firmware/rtc.sh （fw.sh 每次烧完会顺手同步一次）。星期由日期自己算（Sakamoto 算法），不用传。
  • Cmd+[ / Cmd+] / Cmd+N / Cmd+D 都是 WorkBuddy 原生快捷键（应用包内快捷键定义表： prev-task=Meta+[、next-task=Meta+]、new-conversation=Meta+N、toggle-voice-recording=Meta+D）， 不需要在 Mac 侧做任何映射。
  • 「焦点在不在输入框」是整套控制器的命门（v0.4.3 才查清，之前的结论是错的）。 Cmd+D 只绕开了「录音」这一步，绕不开「发送」和「取消」。源码依据： ① 录音 toggle-voice-recording 的处理是 window.addEventListener("keydown", …)， 挂在 window 上，与焦点无关 —— 所以新建对话后照样能录音、文字也照样进输入框； ② 但应用包的 APP_SHORTCUT_IDS（window 级快捷键白名单）里没有 send-message， 它的处理在输入框内部的 React onKeyDown（handleInsertNewline 匹配到 Enter 才 return true 触发发送）。 所以 Enter 只有在焦点位于输入框内时才有效；Cmd+A 同理 —— 焦点在输入框是全选输入内容， 焦点在 body 就是 Chromium 的 select-all，表现为「全选了整个页面的文字且不删除」。 这解释了为什么「已有的对话一切正常、新建的却不行」：跟新建无关，只跟焦点有关 —— 已有对话之所以正常，是因为你之前用鼠标点过输入框，焦点一直在那儿；new-conversation 只跳转、不聚焦。
  • v0.4.3~v0.4.5 的 Tab 遍历、v0.4.6 的 WAKE 档，OCR 实测全部失败 —— v0.4.8 默认改回「不补按」。
    Tab 遍历失败的原因：① Electron 里 Tab 落点跟 DOM 顺序强相关，正向先撞侧边栏一堆按钮、反向也未必落在输入框； ② 新对话的输入框什么时候挂载不确定（等待已从 800ms 放宽到 1800ms 也没救回来）。
    WAKE 档（Cmd+D 双击）实测证伪，这个结论很重要：原以为语音结果回调 text => { appendInputText(text); focusInput(); } 会在录音结束时把焦点送回输入框， 但无声时 WorkBuddy 走的是「未检测到语音内容，请重试」这条分支，焦点不但没回来，反而被语音面板带走。 OCR 对照铁证：输入框里打 QZDD → wake → wipe，结果只剩 QZD（全选失效、 Backspace 退化成删一个字符）；而 esc → wipe 则清空到 placeholder。
    → 所以默认档改回 FOCUS_OFF：宁可不补按，也别发会把焦点弄丢的键。 档位在 设置 → 新建后聚焦 里循环切换（串口 focus 0-7，存 NVS key fmode），WAKE 保留但不再默认。 新建对话这座山还没翻过去，目前新建后需手动点一下输入框。
  • v0.4.4：取消键对齐 VibeKey，改发 ESC（原来是自己设计的 Cmd+A+Delete，错了）。 WorkBuddy 快捷键定义表里的完整答案：stop-generation = Escape、 send-message = Enter、newline = Shift+Enter、new-conversation = Meta+N、 prev/next-task = Meta+[ / Meta+]、toggle-voice-recording = Meta+D。 → Esc 在 WorkBuddy 里的语义是「停止生成」，不是「清空输入框」： 任务正在跑时按它 = 中断；想清空草稿文字得用 WIPE 档（串口 clear 1，= Cmd+A + Delete，需焦点在输入框）。 为什么放弃 Cmd+A+Delete 作默认：焦点不在输入框时它会退化成 Chromium 的 select-all， 表现就是「全选整个页面的文字且不删除」——正是 v0.4.2/v0.4.3 实测到的症状。
  • v0.4.5：取消键 = ESC + 清空草稿，两连击（默认档）。 顺序是 Esc → 等 220ms → Cmd+A → 等 80ms → Backspace。 Esc 负责「停止生成」（不依赖焦点，稳），Cmd+A+Backspace 负责「清空草稿」（需要焦点在输入框）。
    v0.4.8 修掉了「已有对话取消也失效」这个回归：v0.4.6/v0.4.7 里 actClear() 会跟着 focus 设置跑一次唤醒（当时默认 WAKE = Cmd+D 双击），语音面板把焦点带走 → Cmd+A 全选失效、Backspace 只删一个字符，表现就是「取消清不掉草稿」。 修法是取消时一个多余按键都不发（CANCEL_WAKE_FOCUS = 0）—— 已有对话里焦点本来就在输入框（能打字就是证据），唤醒纯属把焦点弄丢。 想恢复唤醒就改 config.h 里的 CANCEL_WAKE_FOCUS 为 1。
    v0.4.6 修了一个隐藏 bug：删除键从 KEY_DELETE(0x4C) 改成 KEY_BACKSPACE(0x2A)。 HID 的 Delete 在 Mac 上等于 Fn+Delete「向前删」，Electron/Chromium 里选区存在时经常不生效； Backspace 才是 Mac 键盘上那颗 delete 键真正发的码 —— 这一条可能就是「全选了但删不掉」的元凶。 合成一档的理由：单独 Esc 说错了重录时旧草稿还在，文字会追加；单独 WIPE 又中断不了正在跑的任务。 最坏情况（焦点在 body）只是「清不掉草稿」而不会误删任何东西，可以接受。 串口 clear 0 退回纯 ESC、clear 1 只要清空。
  • 已有对话全链路 OCR 实测记录（v0.4.8，验证对象 = chronicle skill 对话）。

  • 烧录后一定要重启一次（用户要求，已固化进脚本）。 ESP32-S3 走的是 native USB(CDC)，没有 EN/RTS 硬件复位线，esptool 上传结束后的软复位 偶尔不彻底（BLE/NVS 会留旧状态），所以固件里加了 reboot 串口命令，烧完发一次硬重启。 一键脚本：cores3-firmware/fw.sh —— 自动探测端口 → clean 编译 → 上传 → 发 reboot → 抓启动日志并判断「启动正常 / 有崩溃」。参数 --fast（跳过 clean，改过 .h 别用）、--no-up（只编译）。 坑：NVS 里存的设置不会因为重烧固件而重置（语言、录音方式、取消档、聚焦档都持久化）， 改了默认值想生效要手动发一次串口命令（例如 clear 2）。
  • 屏幕不显示任务名：BLE 键盘是单向的（只能往外发按键），收不回 WorkBuddy 的会话信息， 所以只显示状态（待命 / 录音中 / 已发送 / 已清空）。
  • Keyboard3 只能输 ASCII：中文走语音（内置语音或 macOS 听写）或文本替换，不经过键盘。
  • 语言存在 NVS（namespace cores3，key lang）：重新烧固件不会清掉它。想彻底回到出厂默认，串口发 lang cn。
  • 左滑手势只在应用内生效：桌面已经是根级，滑了没反应。滑到一半反悔（退回左缘再抬手）不会触发。

Mac 端 Music Bridge

cores3-music-bridge/MusicBridge.app（源码 Bridge.swift）：每 2 秒跑 media-control get（MediaRemote），把歌名/歌手/专辑/进度写进 META 特征， 封面压成 160×160 JPEG 后分包写进 ART。首次运行必须在「系统设置 → 隐私与安全性 → 蓝牙」里允许它， 否则 CoreBluetooth 不回调（日志只停在 [bridge] scanning…）。

  • 打包必须显式签名：codesign -s - -f --deep MusicBridge.app。 不签的话签名里是 Info.plist=not bound，TCC 读不到 NSBluetoothAlwaysUsageDescription → 直接 SIGABRT（崩溃报告 namespace=TCC）。签完要看到 Info.plist entries=7。
  • NimBLE 一连上就停广播 → Mac 端扫不到。所以主 loop 每 15 秒拉一次 NimBLEDevice::startAdvertising()（已连接时幂等，不会踢掉现有连接）。
  • QQ 音乐 11.9.1 确认可用：二进制里有 -[QQMusicMainPlayerController setupMPRemoteCommand]，已注册 MPRemoteCommandCenter， 媒体键和 MediaRemote 元数据两条通道都开。 但无 sdef、无 NSAppleScriptEnabled → 原生 AppleScript 不可用， 「喜欢/播放模式」只能走 System Events 点「播放控制」菜单（按名字定位，别用索引）。
  • Apple Music 会劫持媒体键（MediaRemote 给它最高优先级），用之前要 ⌘Q 彻底退出，只关窗口不算。
  • 串口：music 打印当前收到的歌曲状态与封面进度。

v0.5.1 修的两个问题

  • 封面一直不显示（NO ART） —— 缓冲上限定小了。QQ 音乐的封面压成 160×160 JPEG 后是 14777 字节，而 MUSIC_ART_MAX 写的是 12288：首包里的 total 一进来就被判 「超限」丢弃，续包却照收不误 → 缓冲塞满、artTotal 还是 0、 artReady 永远起不来。串口的判据很直观：art=12288/0。
    修法：上限提到 32768（PSRAM 有 8MB），并给续包加了门禁 ——没收到合法首包就丢弃、已收齐还来的重复包也丢弃，不会再出现「半张图被当成整张」。 修完串口是 art=14777/14777 (ready)，日志 [music] 封面解码成功并上屏。
  • 整屏每秒重画一次 —— 封面 JPEG 每秒重新解码，屏幕肉眼可见地闪，而真正要动的只有进度条。
    现在分三档：① 曲目/播放状态/蓝牙变了、或新封面收齐 → 整屏重画（dirty 由 GATT 回调置位）； ② 播放时间往前走了一秒 → 只重画「时间 + 进度条」那一条（clearArea 会补回网格底纹，看不出接缝）； ③ 暂停中或还没到下一秒 → 一个像素都不动。
    关键细节：Mac 端每 2 秒推一次 meta（里面带进度），所以 musParseMeta 必须区分「曲目/状态变了」和「只是进度刷新」， 否则 dirty 每 2 秒置一次，等于又退回整屏闪。

链路与协议

  • 方向跟音乐模块相反：音乐是 Mac 写、设备读；记事本是设备 notify、Mac 订阅。 同一个 NimBLEServer 上再挂一个 NOTE_SVC（OUT 用 NOTIFY、ACK 用 WRITE）。
  • 分包协议跟封面那条对称：首包 [0]=0xA5 + [1..2]=总长(u16 LE)，续包 [0]=0x5A； Mac 端收够总长就拼起来落盘，然后往 ACK 写 0x01。
  • Mac 端不订阅就什么都收不到 —— setNotifyValue(true, for:) 是必须的， 忘了的话 Bridge 日志里永远看不到 [note] →。
  • 没订阅 / 发送失败 / 等回执超时（5 秒） → 内容落 flash 队列（/nq00000001.txt， 编号存 NVS 单调自增），等下次连上自动补发，补发成功才删文件。草稿同样落盘，掉电不丢。 用的是分区表里那块 9.9MB 的分区，跟挂不上的 exFAT TF 卡没关系。
  • ★ 存储用 LittleFS，不用 FFat：FFat 在这块板上能挂载（total=9996KB）但 任何 FILE_WRITE 都失败。为此分区表换成了 partitions.csv（sketch 目录里那份）， 把那块 data 分区的 subtype 从 fat 改成 0x83（littlefs）。
  • ★ open() 的路径不能带挂载点前缀：挂载点给 begin() 用（/littlefs）， 而 open() 要传 fs 内部路径 "/nq00000001.txt"；写成 "/littlefs/nq00000001.txt" 必然打不开 —— FFat 当初"写不了"其实也是这一个坑， 不是文件系统坏了（裸分区擦写实测成功）。排查跑 fs2。
  • 补发和草稿存盘都做了节流（2 秒一次）：队列要扫一遍目录，每帧都扫会把 flash 读爆。 草稿是「停手 2 秒才写一次」，不是每敲一个键就写。
  • ★ 离线笔记带的是书写时间，不是送达时间（v0.6.2）：内容离开编辑区那一刻， 设备把当时的 RTC 烙进正文前面，格式固定 19 字节 [YYYY-MM-DD HH:MM] ； 队列文件里也带着它，所以隔多久补发都不丢。Bridge 认这个前缀就拿它当条目时间和 ## 日期 小标题 —— 昨天写的会归回昨天，并按日期顺序插进正确位置。 没有前缀（老固件 / RTC 归零）才退回 Mac 当前时间。
  • ★ 连上 Bridge 会自动对时（v0.6.2）：CoreS3 的 RTC（BM8563）没有后备电池， 掉电 / 重烧会归零，不对时就没法烙书写时间。所以 Bridge 每次发现 ACK 特征就往里写 7 字节 0x02 + 年-2000 + 月 + 日 + 时 + 分 + 秒（复用 ACK 通道，不新增特征）。 传年月日而不是 epoch —— 设备端没设 TZ，走 epoch 要多处理一次时区。
  • 入队失败时不再清空编辑区（v0.6.2）：原来队列满（32 条）或 fs 不可用时也返回 「成功」，上层就把编辑区清了 —— 那条内容真没了。现在返回失败，内容留在屏幕上。
  • ★ 界面是静态的，不每秒重绘（v0.6.1）：原来挂了 1Hz 节拍，等于每秒整屏重画一次， 肉眼看就是一闪一闪。现在只有「内容真变了」才重画 —— 打字 / 退格 / 清空 / 移光标、 发送结果、以及 BLE 连接与订阅状态、队列数变化时各重画一次，其余时间一个像素都不动。 串口 note 里的 draws= 就是重绘次数：静置时它不涨。
  • 串口：note 看状态；note push Hello 直接推一条（走真实发送路径）； note type Hello 模拟按键打完再按发送（连 appNoteKey() 一起验）。
  • 重刷固件不会丢待发内容：队列文件在独立 data 分区里，fw.sh 只写 app 分区。 实测重启后 Bridge 一订阅就自动补发，queued 归 0、last=已送达。

为什么是「取代时钟」而不是加第 7 个

  • 先试过加第 7 个应用，但 3 列排不下：第 7 个会落到 y=218、底边 296， 超出 240 的屏幕；改成 4 列 × 2 行后 tile 只剩 71px 宽，英文应用名被迫缩短成 CTRL / POMO / SYS / SET。
  • 所以改成用记事本替换时钟，维持 6 个：桌面回到 3 列 × 2 行（tile 94×78）， 英文名恢复全称 CONTROLLER / NOTES / POMODORO / SYSTEM / MUSIC / SETTINGS。
  • 时间并没有丢 —— 状态栏一直在显示 HH:MM，RTC 对时命令 time 也照旧。 时钟源码保留为 app_clock.ino.bak（后缀不是 .ino 就不参与编译），想换回来改个名即可。

目录 cores3-firmware/../cores3-music-bridge/。它干两件事：把 Mac 正在播的歌推给设备屏幕， 以及订阅设备的速记写进 Obsidian。必须常驻 —— 不在跑的时候，设备上的速记只会排队等它。

配置时的两个坑

  • ★ launchctl bootstrap 在后台 shell 里一定失败：AI 工具的 shell、ssh 会话 这类「没有 GUI 审计会话」的进程里，一律报 Bootstrap failed: 5: Input/output error（跟 plist 内容无关，换 Apple 自带的 plist 也一样）。 绕法：osacompile 一个只跑 shell 命令的小程序，用 open 把它送进 GUI 会话去执行 —— bridge.sh 里已经内置了这个降级路径，所以别手工敲 launchctl，走脚本。
  • 不能用 open MusicBridge.app 当自启入口：open 会立刻返回， launchd 以为进程退了，会无限重启。plist 里直接写 .app/Contents/MacOS/MusicBridge 的绝对路径。
  • 改二进制要重新授权蓝牙：./build.sh 重新签名后 cdhash 变了，TCC 可能要再勾一次。 症状是日志停在 [bridge] scanning… 后接 ✗ 蓝牙未授权； 去系统设置 → 隐私与安全性 → 蓝牙勾上，然后 ./bridge.sh restart。
  • KeepAlive=true + ThrottleInterval=10：崩了 10 秒后自动拉起。 实测 kill -9 之后会立刻换个 pid 重新跑起来。
